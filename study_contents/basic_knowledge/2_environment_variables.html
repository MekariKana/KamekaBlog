環境変数の設定

環境変数(PATHやJAVA_HOME)の設定について、整理しておく。

☻
環境変数とは

「変数」は情報を入れる箱のようなもの。

変数定義の例 

# 変数設定
name="かめさん" # "かめさん"という情報を持ったnameという名前の変数が作られる

# 変数の情報を呼び出し
echo $name # "かめさん"が表示される

「環境変数」は、プログラムが動く「環境」に関する情報を定義した変数。 環境変数を設定すると、複数のプログラムで使う共通の情報を共有することができる。 【代表例】 JAVA_HOME：JDKの場所(JAVA_HOME=/opt/homebrew/opt/openjdk/.../Home) PATH：コマンドの実行ファイルを探す場所(PATH=/opt/homebrew/bin:...) HOME：自分のホームディレクトリ(HOME=/Users) SHELL：使用してるシェルの実行ファイルの場所(SHELL=/bin/zsh) ちなみに「export MY_NAME="かめさん"」とすれば、「MY_NAME」という自分独自の環境変数を設定することもできる。

変数と環境変数の違い 

# 普通の変数
JAVA_HOME="Java25のパス" # この設定をしたシェル(bash)の中でだけ使う変数

# 環境変数
export JAVA_HOME="Java25のパス" # このシェルから起動する子プロセスにも継承される

例えば、上記のような環境変数を設定したら、そのシェル(Bash)から呼び出される子プロセスで使用する＄JAVA_HOMEは、Java25が適用される。 ※ただJAVA_HOMEはあくまでJDKの所在地の設定なので、Javaコマンドでこの設定を適用したい場合は以下のPATHの設定も必要となる。

☻
JAVA_HOMEとは

JAVA_HOMEは環境設定のひとつで、Java開発環境（JDK）のホームディレクトリを設定する変数。 Javaを使用するプログラムはjava実行ファイルだけを使うとは限らないので、JDK全体を基準にしてそこから必要なものを探せるようルートを設定しておく。 そのため、Java実行ファイルを使用する時は「$JAVA_HOME/bin/java」となる。 ちなみにHomebrewでのjavaフォルダを以下で整理しておく。 Homebrewとは Macに入れた開発ツールをまとめて管理するための道具。 例えばJavaをインストールする場合、通常①公式サイトからダウンロード②インストーラーを実行③Macに配置、という手順を踏む。 でもHomebrewを使うと、コマンド「brew install openjdk@25」でインストールできる。

Homebrewコマンド 

# インストール
brew innstall openjdk@25

# 検索
brew search openjdk

# アップデート
brew update

# インストール済みソフト更新
brew upgrade

# アンインストール
brew unistall openjdk@25

またHomebrewは単に「ソフトウェアをひとつの箱に入れる」のではなく、ソフトウェア一式を「1つの管理単位」として、インストール・更新・削除などをまとめて扱えるようにしてくれる。 例：HomebrewでJDKをインストールした場合、いくつかjavaフォルダができる。 ①/opt/homebrew/opt/openjdk@25/bin /opt/homebrew/opt/openjdk@25/libexec/openjdk.jdk/Contents/Home/bin/へのリンク。 javaやjavacをコマンドとして見つけてもらうためのPATHに、登録しやすくするための短いルート。 ②/opt/homebrew/opt/openjdk@25/libexec/openjdk.jdk/Contents/Home/bin JDKのHomeディレクトリ。JDK本体(/opt/homebrew/Cellar/openjdk@25/25.0.4.1/libexec/openjdk.jdk/Contents/Home/)へのショートカット。 バージョン管理のために用意されたもの。 ③/opt/homebrew/Cellar/openjdk@25/25.0.4.1/libexec/openjdk.jdk/Contents/Home/ 実際のJava25がインストールされている場所。 ★なぜCellerとopt、2つ別に管理するのか？ バージョンアップした時に、PATHをいちいち変更しなくて済むように、管理用にショートカットフォルダを用意している。 例えば、Java 15.0.4.1がjava 25.0.1にバージョンアップした場合、Cellar/openjdk@25/25.0.4.1と25.0.5の2つのフォルダが存在する可能性がある。 そのとき「JAVA_HOME="/opt/homebrew/Cellar/openjdk@25/25.0.4.1/libexec/..."」となっていると、バージョンアップするたびにパスを変更しなくてはいけないし、もし設定変更し忘れたら古いバージョンを使ってしまう可能性がある。 しかし「JAVA_HOME="/opt/homebrew/opt/openjdk@25/libexec/..."」とoptのフォルダを指定しておくと、homebrewがopt内のリンクを新しいバージョンのJDKフォルダに付け替えてくれるので、自動的に新しいバージョンを指すことになる。 だからバージョン番号を含むCellarの実態を直接指定するより、optを使用した方が扱いやすい。 このように単純にopenjdk@25をインストールするのではなく、簡単に扱えるようにしてくれる。

☻
PATHとは

PATHも環境設定のひとつ。 コマンド(java -vやnode -vなど)は、命令された実行ファイルを探して実行する指示役。 コマンドで命令された時に実行対象のプログラムを探す場所が、PATHに設定されたフォルダになる。

PAHTの例 

# JAVA_HOME：優先して使うJava Versionを指定
export JAVA_HOME="Java25のパス"

# PATHにJAVA_HOMEを追加
export PATH="$JAVA_HOME/bin:$PATH" # 前から優先して実行ファイルを探す。":"で仕切って、次のPATHを指定する

上記のようにPATHを設定すると、Javaを実行する時まずJava25のフォルダから実行ファイルを探す。なければ親プロセスでもともと設定してある環境設定($PATH)の場所から実行ファイルを探す。 コマンドから指示された処理(実行ファイル)を探す場所は主にPATHなので、設定したVarsionの実行ファイルがない等のエラーはまず$PATHに該当のバージョンの実行ファイルがあるか確認する。

注意！ この設定は「親プロセス」には適用されない。 例：zshからbashを呼び出して、bashでJAVA_HOMEやPAHTを設定した場合 zsh→bash→Meven→Java のように実行される場合、bashで設定した環境設定は、bash以下に引き継がれ、zshから実行されるものには適用されない。 また、この場合zshの設定をbashにコピーするようなものなので、bashを退出(exit)したらこの環境設定はリセットされる。 OSの環境設定 逆にOSの環境設定として登録したら、この設定はシャットダウンしても残る。 （Macの場合、環境変数SHELL=/bin/zshにある「./zshrc」ファイルにJAVA_HOMEやPATHを設定しておくと、zsh起動時に最初に.zshrcを読み込んむので、随時設定を維持できる。） また親プロセスの環境設定は子プロセスに引き継がれるので、OSから起動されるプログラムはOSの環境設定から実行ファイルを探す。 しかし、呼び出し側のプログラムやアプリで独自に実行ファイルの場所を指定していれば、そちらが優先されることもある。 例：VScodeからJavaを起動する際、VScodeのJava拡張機能がJDK(Java開発環境一式)の場所を直接指定していることもある。これはOS環境設定より優先される。 例のようにアプリ側で使用する実行ファイルの場所を指定している場合は、この設定を使用したいバージョンのフォルダパスに変更する。
